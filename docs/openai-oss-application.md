## Apply When There Is Evidence

The project is stronger when it has:

- Public stars from real users or maintainers.
- Real issues with sanitized evidence.
- Release history beyond the initial release.
- Clear examples showing recurring failure patterns.
- Maintainer responses that improve docs, references, or safety boundaries.

## Do Not Do This

- Do not buy stars.
- Do not create fake issues.
- Do not invent logs.
- Do not claim official OpenAI endorsement.
- Do not submit private user logs or secrets.

## Application Checklist

- Repository is public.
- GitHub profile is public.
- README explains scope and value in the first screen.
- `CHANGELOG.md` and `ROADMAP.md` exist.
- Issues are real, sanitized, and labeled.
- Latest release notes explain evidence-based changes.
- Applicant can honestly say they are the primary or core maintainer.
